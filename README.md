# cojasclib2

**Common JavaScript Standard for charting libraries.**

cojasclib2 is a small TypeScript library that gives you one library-independent way to describe chart data (datasets, data points, colors), plus a plugin layer that turns that description into whatever a specific charting library expects (Chart.js first).

The idea: build your data once, with a single API, and render it with any supported charting library without rewriting your data-preparation code.

> **Status:** the core data model, automatic colors and the Chart.js plugin are implemented and covered by tests. Chart.js is the only supported library so far.

## Features

- **Dataset factory**: create, retrieve and delete datasets by id. Adding the same id twice won't create a duplicate.
- **Data points**: `x` (number or string), optional `y` and `z`, and free-form per-point `options`.
- **Automatic colors**: each new dataset gets the next color from the active color scheme (Tableau 20 by default), unless you pass one yourself. Colors wrap around when a scheme runs out, and deleting a dataset doesn't make the next one reuse a color.
- **477 built-in color schemes**: Tableau, ColorBrewer and Office palettes, all selectable by name.
- **Chart.js plugin**: produces a ready-to-use Chart.js v3/v4 config for `line`, `bar`, `scatter`, `bubble`, `pie`, `doughnut`, `polarArea` and `radar` charts. No dependency on `chart.js` itself.
- **Plugin architecture**: an abstract `PluginClass` with `transformer()` / `renderer()` hooks for adding other charting libraries.

## Installation

The package isn't published on npm. Install it straight from GitHub:

```bash
npm install github:zeerobug/cojasclib2
# or
pnpm add github:zeerobug/cojasclib2
```

To work on it locally (the project uses pnpm):

```bash
git clone https://github.com/zeerobug/cojasclib2.git
cd cojasclib2
pnpm install
pnpm run build
```

## Usage

```ts
import { DatasetFactory, Chartjs } from 'cojasclib2';
import Chart from 'chart.js/auto';

const factory = new DatasetFactory(); // or new DatasetFactory({ scheme: 'Tableau10' })

// Color is picked automatically from the current scheme
factory.addDataset('sales', 'Monthly sales').addPoints([
  { x: 'Jan', y: 120 },
  { x: 'Feb', y: 135 },
]);

// Explicit color, plus options passed straight to the Chart.js dataset
factory
  .addDataset('costs', 'Monthly costs', '#E15759', { borderDash: [5, 5] })
  .addPoint({ x: 'Jan', y: 80 })
  .addPoint({ x: 'Feb', y: 95, options: { color: '#000' } }); // override one point's color

// Switch to another palette for the datasets you add next
factory.setScheme('YlGnBu5');

// Turn it into a Chart.js chart
const plugin = new Chartjs(factory, { type: 'line', options: { responsive: true } });
new Chart(canvas, plugin.renderer());
// or: plugin.render(Chart, canvas);
```

## Example page

[`examples/index.html`](examples/index.html) is a live demo. It builds a few datasets once, then renders them as any of the 8 Chart.js chart types, using the color scheme you pick. Next to the chart it shows the config generated by `plugin.renderer()`.

The page loads the compiled library straight from `dist/` (Chart.js comes from a CDN), so build first, then serve the repository root over HTTP. Browsers won't load the modules from a `file://` URL.

```bash
pnpm run build
python3 -m http.server 8000   # or any static server
# open http://localhost:8000/examples/
```

## API

### `DatasetFactory`

| Member | Description |
| --- | --- |
| `new DatasetFactory(options?)` | Creates a factory. `options.scheme` sets the color scheme (default `Tableau20`). |
| `addDataset(id, label = '', color = '', options = {})` | Creates a dataset with this `id` or returns the existing one. If you leave out `color`, the next color from the scheme is used. |
| `getDataset(id)` | Returns a dataset, or `undefined`. |
| `getDatasets()` | Returns all datasets as an array. |
| `delDataset(id)` | Removes a dataset. Returns `false` if it didn't exist. |
| `setScheme(name)` | Changes the active color scheme. Throws on an unknown name. |
| `getColor(index?)` | Returns the color at `index` in the active scheme (wrapping around), or the color the next dataset will get. |
| `get()` | Returns the factory, including `datasets` and `datasetCount`. |

### `Dataset`

| Member | Description |
| --- | --- |
| `id`, `label`, `color`, `options`, `data` | Dataset properties. `data` is an array of points. |
| `addPoint(point)` / `addPoints(points)` | Adds points `{ x, y?, z?, options? }`. Chainable. |
| `clear()` | Removes all points. |
| `setColor(color)`, `setLabel(label)`, `setOptions(options)` | Setters (`setOptions` merges). Chainable. |
| `get()` | Returns the dataset. |

### `DataPoint`

`new DataPoint(x, y?, z?, options?)` is a simple container for one point. Plain objects with the same shape work too.

### `colorUtils`

| Member | Description |
| --- | --- |
| `scheme(name)` | Returns a scheme's colors. Throws on an unknown name. |
| `list()` | Names of all bundled schemes. |
| `has(name)` | Whether a scheme exists. |
| `alpha(color, opacity)` | Converts `#rgb` / `#rrggbb` to `rgba(...)`. |

### `Chartjs` plugin

`new Chartjs(factory, { type?, options?, fillOpacity? })`

- `type`: Chart.js chart type, default `line`. Can be changed later with `setType(type)`.
- `options`: copied as-is to the Chart.js `options` object.
- `fillOpacity`: opacity of the area fill for `line` and `radar` (default `0.2`).

Methods: `transformer()` returns the Chart.js `data` object, `renderer()` returns the full `{ type, data, options }` config, and `render(Chart, canvas)` creates the chart.

How the data is mapped:

| Common model | Chart.js |
| --- | --- |
| `dataset.label` | `label` |
| `dataset.color` | `borderColor` and `backgroundColor` (translucent fill for `line` / `radar`) |
| `dataset.options` | Spread onto the dataset last, so any Chart.js dataset property can be set or overridden |
| point `x`, `y` | `{ x, y }` for `line`, `bar`, `scatter`. `line` and `bar` also get a `labels` array of all x values (sorted if numeric) |
| point `z` | Bubble radius `r` (default 3) for `bubble` |
| `pie`, `doughnut`, `polarArea`, `radar` | x values become `labels`, y values the data; missing values are `null` |
| `point.options.color` | Color of that single point, bar or slice |
| other `point.options` | Kept on the data object, available as `context.raw` in Chart.js callbacks (not for label-indexed types) |

For `pie`, `doughnut` and `polarArea`, each slice gets its own color from the factory's scheme.

### Writing a plugin

Extend `PluginClass` and implement both hooks:

```ts
import { PluginClass } from 'cojasclib2';

class MyLibPlugin extends PluginClass<MyData, MyConfig> {
  transformer(): MyData {
    return this.datasetFactory.getDatasets().map(/* ... */);
  }
  renderer(): MyConfig {
    return { series: this.transformer() };
  }
}
```

## Project structure

```
src/
  index.ts            # Public exports
  datasetFactory.ts   # DatasetFactory
  dataset.ts          # Dataset
  dataPoint.ts        # DataPoint
  pluginClass.ts      # Base class for rendering plugins
  types.ts            # Shared TypeScript types
  colors/             # Color schemes (Tableau, Brewer, Office) and helpers
  plugins/chartjs.ts  # Chart.js plugin
tests/                # Jest tests
examples/index.html   # Browser demo (Chart.js)
dist/                 # Compiled output (committed)
```
